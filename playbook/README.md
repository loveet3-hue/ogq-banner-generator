# OGQ 플레이북 자동 생성

매출 엑셀 3개(+반려 데이터)를 넣으면 v2 덱과 같은 포맷으로 초안 pptx가 나옵니다.
디자인은 건드리지 않습니다 — 바꾸는 것은 텍스트 속 숫자, 막대 도형의 크기, 그 위 값
라벨의 위치뿐입니다. 새로 그리는 도형은 없습니다.

## 쓰는 법

### 웹 (권장)

OGQ 콘텐츠 생성기의 **📊 플레이북 만들기** 탭입니다.

```bash
streamlit run web_app.py     # 저장소 최상위에서
```

매출 엑셀 3개를 끌어다 놓고 **플레이북 만들기**를 누르면 됩니다.
`ogq_statistics.xlsx`까지 올리면 심사 반려 슬라이드(36·37장)도 같이 갱신됩니다.

- 파일명에 NOM / SOM / COM(또는 네이버 / SOOP / 채팅)이 있으면 마켓을 알아서 맞춥니다.
  못 맞히면 화면에서 직접 고르면 됩니다.
- **기간은 데이터가 정합니다.** 한 달치를 넣으면 '2026년 3월', 4~6월이면 '2026년 2분기',
  1~6월이면 '2026년 상반기'로 표지·각주·시즌 캘린더가 알아서 맞춰집니다.

### 터미널

```bash
python3 -m playbook.run \
  ~/Downloads/2026_NOM_하반기.xlsx \
  ~/Downloads/2026_SOM_하반기.xlsx \
  ~/Downloads/2026_COM_하반기.xlsx \
  --reject ~/Downloads/ogq_statistics.xlsx --reject-month 2026-12
```

결과: `OGQ_<연도>_<반기>_플레이북_초안.pptx` + `변경내역.md`

### 확인·시험

```bash
python3 -m playbook.test_periods             # 기간 판정 (엑셀 없이 바로)
python3 -m playbook.test_app <엑셀들>        # 웹앱 경로가 도는지
python3 -m playbook.test_next_half <엑셀들>  # 다음 반기 시뮬레이션
python3 playbook/preview.py 결과물.pptx 16 36  # 특정 장을 png로 (맥에서만)
python3 playbook/shape_id.py 36               # 도형ID 찾기
```

## 자동으로 채워지는 것

| 슬라이드 | 내용 |

| 7 | 마켓별 핵심 지표 3개 (테마 매출 비중 · 애니 선호 비율 · 성수기 배수) |
| 8·9·10 | 정지형/애니 선호 비율, 인기 키워드 8개씩 |
| 16·23 | 시간대별 매출 비중 24개 막대 + 집중 구간, 요일별 7개 막대 + 평일/주말 |
| 13·20·27 | TOP25 속성 표 10줄 중 7줄(콘텐츠 유형·기반 분류·도메인·성격·색상·배경·사용 맥락) + KPI 카드 |
| 16·23·30 | 시즌 캘린더 4개월 카드 (음력 명절·수능 날짜 자동) |
| 36 | 반려 사유 12개 항목 비중·건수, KPI 카드 4장, TOP3 상세 카드, 머리말·각주 |
| 37 | 사유별 대응 카드의 반려 비중 배지 |
| 전체 | 기간 표기(시즌 캘린더는 *다음* 반기를 가리키도록 따로 처리) |

## TOP25 속성은 어떻게 채우나

매출 데이터에는 '무엇이 팔렸는지'만 있고 '그게 어떻게 생겼는지'는 없습니다. 그래서
콘텐츠ID로 OGQ마켓을 조회해 스티커 이미지를 받아 옵니다.

    https://ogqmarket.naver.com/artworks/sticker/detail?artworkId=<콘텐츠ID>

**실제 이미지에서 잴 수 있는 세 줄만 채웁니다.**

| 줄 | 재는 방법 |
| --- | --- |
| 콘텐츠 유형 | 스티커가 PNG인지 GIF인지 |
| 색상 스타일 | 색이 있는 픽셀의 비율과 채도 (무채색·파스텔·원색·어두운 톤) |
| 배경 유형 | 알파 채널의 투명 픽셀 비율 |

나머지 일곱 줄(텍스트 비중·텍스트 종류·기반 분류·콘텐츠 도메인·상세 성격·라인 스타일·
사용 맥락)은 **손대지 않습니다.** 마켓 태그로 근사해 봤지만 사람이 눈으로 본 것과
갈리는 일이 잦았습니다(채팅+ 상세 성격: 자동 '공손·정중' vs 사람 '귀여운').
근거가 약한 값을 채워 넣느니 이전 판이 남아 있는 편이 낫다고 보고 뺐습니다.

이미지로 재는 것은 잘 맞습니다.

| | 자동 | v2 덱(사람) |
| --- | --- | --- |
| SOOP 콘텐츠 유형 | 애니메이션 90.3% | 89.9% |
| SOOP 시리즈 매출 | 29.6% | 28.9% |
| 채팅+ GIF 비중 | 70.8% | 72.0% |

마켓 조회 결과는 임시폴더에 저장하므로 두 번째 실행부터 빠릅니다.

## 8·9·10장 비율 막대

글자('정지형 91%')만 바꾸고 **막대 길이는 건드리지 않습니다.** 이 막대는 손으로 다듬어져
슬라이드마다 구조가 다르고(어떤 장은 글자만 바뀌고 막대는 그대로입니다) 자동으로
늘였다 줄였다 하면 디자인이 망가집니다. 실행할 때마다 "막대 길이를 확인해 달라"고
알려 줍니다.

## 사람이 정해야 하는 것

실행할 때마다 목록으로 알려줍니다.

- **13·20·27장** — TOP25 표에서 이미지로 못 재는 일곱 줄, 왼쪽 '유형별 매출 비중' 막대
- **8·9·10장** — 비율 막대의 길이 (글자는 자동)
- **4·5·33·34·35장** — 회사·마켓 소개와 제작 가이드. 규격이 바뀔 때만 손봅니다.

## 알아둘 것

**1. 정지형/애니 비중은 매출 기준입니다**
`config.CTYPE_BASIS = 'rev'`. 기준마다 숫자가 이만큼 다릅니다.

| | 매출(현재) | 건수 | 구매자 |
| --- | --- | --- | --- |
| NAVER 정지형 | **90.8%** | 94.3% | 93.0% |
| SOOP 애니 | **70.4%** | 61.2% | 50.8% |
| 채팅+ 애니 | **58.3%** | 45.1% | 45.7% |

v2 덱의 SOOP 90% · 채팅+ 72%는 어느 기준과도 맞지 않아 근거를 댈 수 없었습니다.
채팅+는 **기준에 따라 우위가 뒤집힙니다** — 매출로는 애니 58.3%가 앞서지만 몇 개를
샀는지로 보면 정지형 54.9%가 앞섭니다(애니 2,500원 / 정지형 1,500원). 그래서 8·9·10장
제목을 '콘텐츠 유형 선호도'에서 '콘텐츠 유형별 매출 비중'으로, 7장 SOOP 설명줄을
'선호 비율(정지형 대비)'에서 '매출 비중(전체 매출 대비)'으로 고쳤습니다.
기준을 바꾸려면 config.py와 함께 이 캡션들(overrides.py)도 손봐야 합니다.

**1-2. 비율 막대는 폭이 곧 값입니다**
8·9·10장의 가로 띠는 폭으로 비중을 나타냅니다(90.8% → 5.13″ 중 4.658″).
글자만 바꾸면 그림이 값과 어긋나므로 `fill_ctype_bar`가 폭과 글자를 함께 갱신합니다.

**2. 심사 문구는 바뀝니다**
2026-07부터 반려 문구가 새 어투로 리라이팅됐습니다("~되었어요"). 그때 1,342건짜리
중복 사유가 통째로 '기타'에 빠졌습니다. 그래서 미분류가 5%를 넘으면 경고와 함께
미분류 상위 문구를 찍어 줍니다. 경고가 뜨면 `reject.py`의 `RULES`에 표현을 추가하세요.

**3. 메모리**
이 앱은 배너 생성기·카드뉴스와 메모리를 나눠 씁니다. 매출 파일이 29만 행이라
`ingest.py`가 (1) 쓰는 열만 (2) openpyxl로 한 줄씩 흘려 읽고 (3) 되풀이되는 값은
category로 담습니다. 이걸로 최대 사용량이 518MB → 365MB로 줄었습니다.
값은 그대로인 것을 확인했습니다. 더 큰 파일이 들어와 클라우드에서 죽으면
터미널(`python3 -m playbook.run`)로 돌리면 됩니다.

**4. 막대는 넘치지 않습니다**
가장 큰 값이 템플릿의 가장 큰 막대 높이를 그대로 쓰고 나머지는 비례로 줄어듭니다.
값이 아무리 커져도 차트 밖으로 나가지 않습니다.

**5. 템플릿을 다시 내보내면**
`overrides.py`와 `spec.TEXT_BINDINGS`는 도형ID로 자리를 잡습니다. 도형을 지웠다 새로
만들면 ID가 바뀌므로 `shape_id.py`로 새 ID를 확인해 고쳐야 합니다. 위치나 색만 옮기는
건 괜찮습니다.

## 2026-09-02 최종본(v2_) 대비 맞춘 것

Google Slides 최종본과 생성 결과를 39장 전부 비교해(평균 일치율 98.8%) 어긋난 곳을 고쳤습니다.

- **TOP25 카드·표의 잣대를 문구에서 읽습니다.** 예전에는 '콘텐츠 유형' 줄만 무조건 판매 수로
  쟀는데, 최종본 카드는 '매출 비중'(NOM·SOM)과 '(이모티콘 수 기준)'(COM)으로 서로 다릅니다.
  이제 `attrs.basis_of()` 가 문구를 보고 매출액 / 판매 수 / 콘텐츠 수 중에서 고릅니다.
  NOM 정지형 94.0%, COM 애니 70.8% 처럼 최종본 숫자와 맞습니다.
- **표 머리글 '매출 비중'을 그대로 둡니다.** 모든 줄이 매출 기준이 되어 더 이상 '비중'으로
  바꿀 이유가 없습니다.
- **속성 표 아홉 줄은 자동으로 채우지 않습니다.** 분류기와 최종본은 분류 체계부터 다릅니다
  (최종본 '감탄사·의성어 / 동물 의인화 / 캐릭터 리액션' ↔ 분류기 '표준어 / 동물 / 방송·게임').
  덮어쓰면 사람이 정리해 둔 표가 나빠지므로 손대지 않고, 분류기 추정치는 변경내역 맨 아래
  **참고값** 표에 남깁니다.
- **시즌 캘린더 표제**를 '2026 9~12월' → **'2026 하반기'** 로 바꿨습니다(최종본 표기).
  네 달이 한 반기에 들면 반기로, 반기를 걸치면 달 범위로 적습니다.
- **비율 표기를 소수 한 자리로** 통일했습니다(38% → 38.0%).
- **OCR 과검출 경고**: '텍스트 포함 콘텐츠 비중'이 100%로 나오면 눈으로 확인하라고 알려 줍니다.
