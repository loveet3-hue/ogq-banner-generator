# OGQ 플레이북 자동 생성

매출 엑셀 3개(+반려 데이터)를 넣으면 v2 덱과 같은 포맷으로 초안 pptx가 나옵니다.
디자인은 건드리지 않습니다 — 바꾸는 것은 텍스트 속 숫자, 막대 도형의 크기, 그 위 값
라벨의 위치뿐입니다. 새로 그리는 도형은 없습니다.

## 쓰는 법

### 웹 (권장)

OGQ 콘텐츠 생성기의 **📊 플레이북 만들기** 탭입니다.

```bash
streamlit run web_app.py     # 저장소 최상위에서
```

매출 엑셀 3개를 끌어다 놓고 **플레이북 만들기**를 누르면 됩니다.
`ogq_statistics.xlsx`까지 올리면 심사 반려 슬라이드(36·37장)도 같이 갱신됩니다.

- 파일명에 NOM / SOM / COM(또는 네이버 / SOOP / 채팅)이 있으면 마켓을 알아서 맞춥니다.
  못 맞히면 화면에서 직접 고르면 됩니다.
- 상반기·하반기는 데이터 날짜로 판단합니다.

### 터미널

```bash
python3 -m playbook.run \
  ~/Downloads/2026_NOM_하반기.xlsx \
  ~/Downloads/2026_SOM_하반기.xlsx \
  ~/Downloads/2026_COM_하반기.xlsx \
  --reject ~/Downloads/ogq_statistics.xlsx --reject-month 2026-12
```

결과: `OGQ_<연도>_<반기>_플레이북_초안.pptx` + `변경내역.md`

### 확인·시험

```bash
python3 -m playbook.test_app <엑셀들>        # 웹앱 경로가 도는지
python3 -m playbook.test_next_half <엑셀들>  # 다음 반기 시뮬레이션
python3 playbook/preview.py 결과물.pptx 16 36  # 특정 장을 png로 (맥에서만)
python3 playbook/shape_id.py 36               # 도형ID 찾기
```

## 사람이 정해야 하는 것

실행할 때마다 목록으로 알려줍니다.

- **13·20·27장 TOP25 속성 태깅** — 텍스트 비중·기반 분류·색상 스타일 등. 콘텐츠를 눈으로
  보고 분류하는 값이라 거래 데이터에 없습니다.
- **16·23·30장 시즌 캘린더** — 명절·기념일·시험 일정. 달력 정보입니다.
- **7장 주 연령층** — 거래 데이터에 구매자 인구통계가 없습니다.
- **4·5·33·34·35장** — 회사·마켓 소개와 제작 가이드. 규격이 바뀔 때만 손봅니다.

## 알아둘 것

**1. 정지형/애니 비중은 매출 기준입니다**
`config.CTYPE_BASIS = 'rev'`. 기준마다 숫자가 이만큼 다릅니다.

| | 매출(현재) | 건수 | 구매자 |
| --- | --- | --- | --- |
| NAVER 정지형 | **90.8%** | 94.3% | 93.0% |
| SOOP 애니 | **70.4%** | 61.2% | 50.8% |
| 채팅+ 애니 | **58.3%** | 45.1% | 45.7% |

v2 덱의 SOOP 90% · 채팅+ 72%는 어느 기준과도 맞지 않아 근거를 댈 수 없었습니다.
채팅+는 **기준에 따라 우위가 뒤집힙니다** — 매출로는 애니 58.3%가 앞서지만 몇 개를
샀는지로 보면 정지형 54.9%가 앞섭니다(애니 2,500원 / 정지형 1,500원). 그래서 8·9·10장
제목을 '콘텐츠 유형 선호도'에서 '콘텐츠 유형별 매출 비중'으로, 7장 SOOP 설명줄을
'선호 비율(정지형 대비)'에서 '매출 비중(전체 매출 대비)'으로 고쳤습니다.
기준을 바꾸려면 config.py와 함께 이 캡션들(overrides.py)도 손봐야 합니다.

**1-2. 비율 막대는 폭이 곧 값입니다**
8·9·10장의 가로 띠는 폭으로 비중을 나타냅니다(90.8% → 5.13″ 중 4.658″).
글자만 바꾸면 그림이 값과 어긋나므로 `fill_ctype_bar`가 폭과 글자를 함께 갱신합니다.

**2. 심사 문구는 바뀝니다**
2026-07부터 반려 문구가 새 어투로 리라이팅됐습니다("~되었어요"). 그때 1,342건짜리
중복 사유가 통째로 '기타'에 빠졌습니다. 그래서 미분류가 5%를 넘으면 경고와 함께
미분류 상위 문구를 찍어 줍니다. 경고가 뜨면 `reject.py`의 `RULES`에 표현을 추가하세요.

**3. 메모리**
이 앱은 배너 생성기·카드뉴스와 메모리를 나눠 씁니다. 매출 파일이 29만 행이라
`ingest.py`가 (1) 쓰는 열만 (2) openpyxl로 한 줄씩 흘려 읽고 (3) 되풀이되는 값은
category로 담습니다. 이걸로 최대 사용량이 518MB → 365MB로 줄었습니다.
값은 그대로인 것을 확인했습니다. 더 큰 파일이 들어와 클라우드에서 죽으면
터미널(`python3 -m playbook.run`)로 돌리면 됩니다.

**4. 막대는 넘치지 않습니다**
가장 큰 값이 템플릿의 가장 큰 막대 높이를 그대로 쓰고 나머지는 비례로 줄어듭니다.
값이 아무리 커져도 차트 밖으로 나가지 않습니다.

**5. 템플릿을 다시 디자인하면**
`overrides.py`와 `spec.TEXT_BINDINGS`는 도형ID로 자리를 잡습니다. 도형을 지웠다 새로
만들면 ID가 바뀌므로 `shape_id.py`로 새 ID를 확인해 고쳐야 합니다. 위치나 색만 옮기는
건 괜찮습니다.
